# 運用担当者ガイド

この文書は、手具セット管理アプリを開発者本人以外でも復旧・確認できるようにするための引き継ぎ資料です。

## サービス一覧

| 対象 | 場所 | 用途 |
| --- | --- | --- |
| 本番アプリ | https://prop-setting.vercel.app | メンバーと管理者が使うPWA |
| ソースコード | https://github.com/harupen26/prop-setting | 変更履歴、障害調査、引き継ぎ資料 |
| Supabase | `harupen26's Project` | プロジェクトデータとリアルタイム共同編集 |
| Vercel | `prop-setting` | GitHubの`main`から本番アプリを自動公開 |

パスワード、Supabaseの`service_role`キー、データベースパスワード、個人アクセストークンは、この文書やChatGPTの共有リンクに書かないでください。

## 共同運用者を追加する

### Supabase

休止したプロジェクトを再開できるようにするには、共同運用者を`Administrator`として組織に招待します。`Developer`はプロジェクト設定を変更できないため、再開担当には向きません。

1. 共同運用者が自分のメールアドレスでSupabaseアカウントを作る。
2. 所有者がSupabase Dashboardを開く。
3. 左上の組織名から`Team`または`Team Settings`を開く。
4. `Invite member`を押し、共同運用者のメールアドレスを入力する。
5. Roleは`Administrator`を選ぶ。
6. 共同運用者が24時間以内に招待メールを開いて承認する。
7. 共同運用者のアカウントで`harupen26's Project`が見えることを確認する。

`Administrator`はデータベースも操作できる強い権限です。信頼できる1人だけを追加し、アカウントやパスワードそのものは共有しません。

### GitHub

リポジトリは公開されているため、コードやこの資料はURLだけで閲覧できます。修正やPull Requestも担当してもらう場合は、GitHubのリポジトリで`Settings > Collaborators > Add people`から追加します。

Vercelは無料のHobby運用です。共同運用者のコミットがそのまま本番デプロイされない場合があります。通常は共同運用者がPull Requestを作成し、所有者が確認して`main`へ反映します。完全なVercelチーム共同管理は有料プランが必要になる場合があります。

## Supabaseが休止したとき

無料プランでは、データベース利用が少ない状態が約1週間続くと休止することがあります。

1. https://supabase.com/dashboard を開く。
2. 組織`harupen26's Org`を選ぶ。
3. プロジェクト`harupen26's Project`を選ぶ。
4. `Resume project`を押して確定する。
5. 数分待つ。
6. 本番アプリを再読み込みする。
7. 画面下部が`DB同期: 最新`になることを確認する。

休止中もデータはすぐには削除されません。慌てて新しいSupabaseプロジェクトを作ったり、Vercelの環境変数を変更したりしないでください。

## 障害時の確認順

### `DB同期: 要確認`の場合

1. インターネット接続を確認する。
2. Supabase DashboardでプロジェクトがPausedになっていないか確認する。
3. Pausedなら`Resume project`を押す。
4. 数分後にアプリを閉じて開き直す。
5. 直らなければ、発生時刻、招待ID、画面のスクリーンショットを記録してCodexへ相談する。

### アプリが更新されない場合

1. GitHubの`main`に目的のコミットがあるか確認する。
2. GitHubのコミット画面でVercelが成功しているか確認する。
3. ブラウザを再読み込みする。
4. ホーム画面から起動している場合は、一度完全に閉じて開き直す。

### データがおかしい場合

`初期データに戻す`、プロジェクト削除、シート削除、SQL実行は行わないでください。最初に次を記録します。

- 発生時刻
- プロジェクトの招待ID
- 操作した参加者とシート名
- 直前に行った操作
- 画面のスクリーンショット
- `DB同期`の表示

## Codexへ相談する方法

この会話の共有リンクは経緯を見るための参考資料として使えます。ただし、共有リンクだけではSupabaseやGitHubの権限は渡らず、会話内容も運用資料として更新され続けるわけではありません。

継続的なサポートには、共同運用者自身のCodexまたはChatGPTで新しい会話を作り、GitHubリポジトリとこの文書を共有します。Codexでコード変更まで行う場合は、リポジトリをPCに取得して、そのフォルダーをワークスペースとして開きます。

最初のメッセージには次の文をそのまま使えます。

```text
手具セット管理アプリの運用・トラブル対応を手伝ってください。

リポジトリ:
https://github.com/harupen26/prop-setting

本番アプリ:
https://prop-setting.vercel.app

最初にREADME.mdとdocs/operator-guide.mdを読み、現在の構成と安全な確認手順を把握してください。

無料運用を最優先にしてください。データ削除、SQL実行、Supabaseの設定変更、Vercelの環境変数変更、本番デプロイは、原因と影響を説明してから行ってください。パスワード、service_roleキー、データベースパスワード、個人アクセストークンは会話に貼らないでください。

まず症状を整理し、読み取りだけでできる確認から始めてください。DB同期の問題なら、Supabaseの休止状態、本番アプリのDB同期表示、GitHubとVercelのデプロイ状態を順番に確認してください。
```

## 変更を本番へ出すとき

変更後は必ず次を通します。

```bash
pnpm typecheck
pnpm test
pnpm exec expo export --platform web
```

その後、GitHubへ反映し、Vercelのデプロイ成功と本番画面を確認します。本番のデータを使う削除テストは行わず、削除処理はローカル環境で確認します。
